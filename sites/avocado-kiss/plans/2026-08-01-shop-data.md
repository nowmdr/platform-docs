# Curated Shop — Data Layer Implementation Plan (Spec B)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Back the Curated Shop with real data — `avocado_kiss` migration (products, shop_categories, 3 curation tables), Supabase loaders, seeded content — so the UI from Spec A runs on the live DB unchanged.

**Architecture:** New migration `0007_shop.sql` following the RLS/grant conventions of `0001`. Rewrite the **bodies** of `lib/shop.ts` (created fixtures-backed by Spec A) to query Supabase; keep every exported signature and type identical so the UI is untouched. Text category reference (no FK), like `recipes.category`. Curation via three join tables modeled on `home_slots`.

**Tech Stack:** Supabase (Postgres, schema `avocado_kiss`, bucket `avocado-kiss-photos`), supabase-js (publishable key), Next.js 16 RSC.

**PREREQUISITE:** Spec A (`2026-08-01-shop-ui.md`) is merged — `lib/types.ts`, `lib/shop.ts`, `lib/shop-fixtures.ts` and all components/pages exist and build on fixtures. This plan swaps the data layer under them.

**Spec:** `platform-docs/sites/avocado-kiss/specs/2026-08-01-shop-data-design.md` — read fully first.
**Reference:** cozycorner `lib/products.ts` (loader patterns: pagination determinism, `resolveProductImage`, related-with-fallback) and avocado `lib/content.ts` (`fetchHomeSlots` `!inner`/`is_published` embed pattern) + migration `0001_avocado_kiss_schema.sql` (RLS/grants/`is_admin()` template).

**Working rules:** on branch `main`; do NOT push without permission. Apply migration via Supabase MCP/dashboard (standard workflow). Verify `npm run build` + `npm run lint` green after the swap. Env: publishable key only.

## Task 4: Rewrite loaders to Supabase

**Files:** Modify `lib/shop.ts`

- [ ] **Step 1:** Replace each loader body with Supabase queries per spec §3, keeping signatures/return types identical:
  - `fetchShopCategories` — `order('position').order('name')`.
  - `fetchShopCategoryBySlug` / `fetchShopCategorySlugs`.
  - `fetchProductsPage` — optional `eq('category', categorySlug)`; `.order('created_at',{ascending:false}).order('id',{ascending:false}).range(from,to)`; attach `category_name` (lookup/embed to `shop_categories`). Keep client-safe (no `server-only`) — `ProductGrid` calls it in the browser.
  - `fetchEditorsPicks` — `shop_editors_picks` embed `product:products(*)`, `order('position')`, cap 4; attach `category_name`.
  - `fetchProductBySlug` / `fetchProductSlugs`.
  - `fetchProductPairings` — `product_pairings` `eq('product_id', product.id)` embed `paired:products(*)` `order('position')` → 3 products.
  - `fetchRelatedReading` — `product_reading` `eq('product_id', product.id)` embed `recipe:recipes!inner(slug,title,category,hero_image_path,is_published)` `eq('recipe.is_published', true)` `order('position')` → project to `ReadingItem` (`href='/recipes/'+slug`, `eyebrow=category`, `imagePath=hero_image_path`).
  - `resolveProductImage` — bucket `avocado-kiss-photos`, `NEXT_PUBLIC_SUPABASE_URL`; relative→public URL (optimize), external→`unoptimized`. `formatPrice`, `productPath` unchanged.
- [ ] **Step 2:** Keep the exact client-safe vs `server-only` split Spec A established so `ProductGrid`'s browser import still resolves.
- [ ] **Step 3:** `npx tsc --noEmit` clean. Commit `feat(shop): Supabase loaders`.
